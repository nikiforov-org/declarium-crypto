# Стенд `@declarium/crypto`

Отладочный фронтенд. В пакет npm не попадает (в `package.json` библиотеки стоит
аллоулист `files`), в репозитории лежит — проверять средства подписи можно
только на живой машине, и стенд для этого нужен под рукой.

```sh
npm install
npm run dev      # https://localhost:5180
```

Библиотека подключается **исходниками** из `../src` через alias в
`vite.config.ts`: правки видно сразу, в стеке ошибок стоят настоящие файлы.
Пересобирать `dist` не нужно.

## Устройство

То же правило, что в библиотеке: **одна задача — один модуль, модули не знают
друг о друге.** Панели не ссылаются одна на другую, `main.ts` только собирает
страницу.

```
src/main.ts              сборка: порядок панелей, больше ничего

src/shell/dom.ts         разметка без фреймворка
src/shell/panel.ts       каркас панели
src/shell/log.ts         журнал, timed(), разбор ошибок
src/shell/session.ts     текущий сеанс — единственное общее состояние

src/panels/providers.ts  1. средства подписи
src/panels/login.ts      2. вход
src/panels/signing.ts    3. подпись, проверка, разбор CMS
src/panels/kontur-raw.ts 4. сырой канал к хосту Контура

src/kontur/bridge.ts     нетипизированный мост для панели 4
```

Связь между панелями ровно одна: вход кладёт сеанс в `shell/session.ts`,
подпись на него подписывается. Кто открыл сеанс и каким средством, панели
подписи не важно — ей достаточно интерфейса `Session`. Понадобится ещё панель,
которой нужен сеанс, — подпишется тем же способом, существующие трогать не
придётся.

Панель 4 — отладочный инструмент стенда, а не часть маршрута: `KonturProvider`
про неё не знает и пользуется собственным типизированным транспортом из
`src/kontur/` библиотеки.

## Почему https

Расширения средств подписи ведут списки доверенных узлов и сверяют их с
источником страницы — у `http://localhost` и `https://localhost` он разный.
Проверять библиотеку надо в тех же условиях, в которых она будет работать на
сайте.

Сертификат выпускается сам при первом запуске: `mkcert`, если он есть в системе
с установленным локальным УЦ (браузер тогда не ругается), иначе openssl и
самоподписанный. Ключ и сертификат лежат в `certs/` и в репозиторий не
попадают. Перевыпуск — `npm run cert`. Дополнительные имена:

```sh
DEV_CERT_HOSTS=stand.local,192.168.1.10 npm run cert
```

## Что на странице

1. **Средства подписи** — `detect()` у каждого провайдера по отдельности, с
   полным `ProviderStatus`. Опрос идёт по очереди: нативные плагины, поднятые
   одновременно, спорят за токен и считыватель.
2. **Вход** — весь `authenticate()`: опрос → список сертификатов → выбор →
   сеанс. При неудаче показывает `NoProviderError.attempts` целиком.
3. **Подпись и проверка** — открепленная CAdES-BES по байтам из верхнего поля.
   Подпись лежит в отдельном редактируемом поле, так что проверять и разбирать
   можно и чужую: пришедшую с сервера, из файла, от другой стороны. «Разобрать
   CMS» достаёт вложенные сертификаты и средства подписи не требует вовсе —
   это чистая работа с байтами. Полезная проверка: подписать, поменять текст,
   проверить — должно перестать подтверждаться.
4. **Контур.Плагин — сырой канал** — запрос уходит хосту `kontur.plugin` как
   есть, мимо провайдера. Нужен для команд, которых в библиотеке нет, и чтобы
   видеть ответ хоста без обёртки.
5. **Журнал** — все вызовы со временем выполнения.
