# @declarium/crypto

Вход по сертификату и подпись документов в браузере: **Рутокен Плагин** и
**КриптоПро ЭЦП Browser plug-in** за одним интерфейсом.

Закрытый ключ не покидает носитель. Сервер в подписи не участвует.

## Установка

```sh
pnpm add @declarium/crypto
```

## Использование

```ts
import { authenticate } from '@declarium/crypto'

const session = await authenticate({
  // Показать список и вернуть идентификатор выбранного.
  chooseCertificate: (list) => showDialog(list),
  // Нужен только Рутокену и только при обращении к закрытому ключу.
  requestPin: () => askPin(),
})

session.provider          // 'rutoken' | 'cryptopro'
session.certificate       // разобранный сертификат

const signature = await session.sign(bytes)            // CAdES-BES, открепленная
const verdict = await session.verify(signature, bytes) // { valid, reason? }
```

## Выбор средства подписи

Опрашивается сначала Рутокен, затем КриптоПро. Порядок задаётся:

```ts
authenticate({ order: ['cryptopro'], … })
```

Средство считается пригодным, только если оно отвечает **и** у него есть хотя бы
один сертификат. Установленный плагин Рутокена без вставленного токена или
КриптоПро с пустым хранилищем «Личные» пропускаются — иначе они перекрывали бы
работающее средство.

Опрос останавливается на первом пригодном: второе средство не создаётся и на
страницу не попадает.

Если не подошло ни одно, `authenticate` бросает `NoProviderError` с перечнем
попыток — по каждому средству отдельная причина и совет.

## Выбор сертификата и ПИН

`chooseCertificate` вызывается всегда, в том числе когда сертификат
единственный: пользователь должен видеть, чем подписывает.

`requestPin` вызывается лениво, при первом обращении к закрытому ключу, и только
для Рутокена — КриптоПро показывает собственное окно ввода. Список сертификатов
у обоих средств читается без ПИН, поэтому выбор идёт раньше.

## Что означает результат проверки

`session.verify()` выполняется **локально**, нативным средством подписи на
машине пользователя. Сеть не используется.

Проверяется, что данные не изменились после подписания и что подпись сделана
владельцем закрытого ключа от сертификата, вложенного в неё.

Не проверяется, можно ли доверять самому сертификату: не отозван ли он и выдан
ли аккредитованным удостоверяющим центром. Для этого нужны построение цепочки и
OCSP, то есть сеть и корневые сертификаты.

Поэтому положительного результата локальной проверки недостаточно для
аутентификации пользователя: подписывать следует выданный сервером одноразовый
код, а решение о доступе принимать на сервере.

## Разбор сертификата

Поля читаются из DER через `pkijs`, а не из строки субъекта: КриптоПро отдаёт её
в кавычной форме с кириллическими ключами (`CN="ООО ""РОМАШКА""", ИНН=…`),
Рутокен — длинными именами (`commonName=…, INN=…`). Из DER оба средства дают
одинаковый результат, и дополнительно доступны расширения, серийный номер и
точные даты.

Российские идентификаторы разложены по именованным полям:

| поле | OID |
|---|---|
| `innFl` — ИНН физического лица | 1.2.643.3.131.1.1 |
| `innUl` — ИНН юридического лица | 1.2.643.100.4 |
| `ogrn` | 1.2.643.100.1 |
| `ogrnip` | 1.2.643.100.5 |
| `snils` | 1.2.643.100.3 |

Остальные атрибуты — в `subject.attributes` по идентификатору.

`certificate.der` содержит сертификат целиком: его передают серверу для проверки
подписи. Это открытая часть; закрытый ключ носитель не покидает.

Отдельно доступны `parseCertificate`, `parseCertificateFromBase64` и
`certificatesFromCms` — последняя достаёт сертификаты, вложенные в подпись, и
позволяет опознать подписанта, не обращаясь к носителю.

## Что должно быть установлено у пользователя

**Рутокен**: токен, Рутокен Плагин и расширение браузера «Адаптер Рутокен
Плагин». Библиотеки `librtpkcs11ecp` недостаточно — она нативная, странице
недоступна.

**КриптоПро**: КриптоПро CSP, ЭЦП Browser plug-in **не ниже 2.0.15400** и
расширение «Extension for CAdES Browser Plugin». Более ранние версии
использовали расширение на Manifest V2, который Chrome больше не поддерживает.

Сертификаты не попадают в хранилище «Личные» автоматически: контейнеры могут
быть видны, а хранилище при этом пусто. Установка — `csptestf -absorb -certs`
либо `certmgr -inst -cont`.

## Устойчивость к отказам нативной части

Нативные компоненты средств подписи живут в отдельных процессах и при сбое могут
перестать отвечать, не возвращая ошибку. Поэтому срок ожидания стоит на каждом
обращении к плагину и общим пределом на опрос средства: вход не зависает, а
переходит к следующему средству с внятной причиной.

## Особенности вендорских API

Учтены внутри библиотеки; перечислено для тех, кто будет её сопровождать.

**Рутокен, формат подписываемых данных.** Двоичные данные передаются в base64 и
требуют `dataFormat = DATA_FORMAT_BASE64`. При `DATA_FORMAT_PLAIN` подписывается
текст base64-представления, а не сами данные, и подпись не подтверждается.
Параметр `base64` в опциях `sign` на формат входа не влияет.

**Рутокен, `requireCades` и `verifyCertificate` при проверке.** Обе опции
включают проверку издателя и требуют корневых сертификатов на устройстве:
`requireCades` отвечает 54 «Unable to get local issuer certificate»,
`verifyCertificate` — 12 «No CA certificates found». Библиотека их не использует,
так как проверяет криптографию, а не доверие к сертификату.

**Рутокен, форма ошибки.** Промис отклоняется объектом
`{ message: <число>, error, description }`: в `message` числовой код, смысл — в
`description`.

**КриптоПро, `About.CSPVersion()`** возвращает COM-объект, а не строку; строка
получается через `toString()`. `About.Version` при этом строка.

**КриптоПро, `Certificate.Export`** принимает только кодировку Base64; на Binary
отвечает `0x80070057`.

**КриптоПро, выбор алгоритма шифрования** через `propset_Algorithm` в версии
2.0.15700 не поддерживается — на значения ГОСТ отвечает `0x80004001`. Алгоритм
определяет CSP по ключу получателя.

## Служебный вход

`@declarium/crypto/internals` открывает средства подписи по отдельности:
пошаговый опрос, чтение хранилища «Другие пользователи», шифрование на
получателей. Это не публичный контракт и может измениться без предупреждения.
Для входа и подписи достаточно `authenticate()`.

## Окружение

Только браузер: используются `window`, `document`, `atob`/`btoa` и
`crypto.getRandomValues`.
